Codex 配置修复助手 1.2.2

使用方法
1. 将 ZIP 解压到本地目录，保留所有文件。
2. 双击 CodexConfigRepair.exe。
3. 选择 .codex 目录，以及 config.toml-bf 等旧配置文件（可选）。
4. 点击“扫描并预览”。确认当前模型和登录方式保留，查看历史处理数量与明细。
5. 保存正在进行的工作，退出 Codex 桌面程序及 Codex 命令行。
6. 返回修复助手，点击“备份并修复”。完成后重新打开 Codex。

切换直连与中转
1. 进入“连接切换”。已有配置时，点击“读取配置文件”，选择 config.toml、
   config.toml-bf、.bak 备份或其他 TOML 文件，自动回填连接、地址、模型及可用密钥。
   支持 UTF-8、UTF-8 BOM、带 BOM 的 UTF-16；密钥默认隐藏。
2. 也可手动选择 OpenAI 直连或第三方中转。
   直连沿用目标目录现有官方登录；中转需要接口基础地址与 API 密钥。
   地址示例：https://gateway.example.com/v1（不包含 /responses）。
   中转服务必须支持 Responses API，模型名称可选填写。
3. 点击“预览切换”，退出 Codex 后点击“备份并切换”。
4. 完成后重新打开 Codex。中转地址不变时，密钥留空可沿用保存值。
   更换地址需要重新输入对应密钥。
读取配置只回填表单，不直接覆盖目标文件，不复制项目、MCP 或登录文件。
多个提供方按源主配置的 model_provider 读取；仅支持主配置的官方直连
和 Responses API 中转，独立 profile 或动态认证等配置会提示不支持。
环境变量密钥在当前进程中可用时读取，缺失时需手动填写。
修改源文件不会自动更新表单；需要新内容时重新读取后预览。
密钥以明文保存在本机 config.toml；输入框默认隐藏，检测报告脱敏。
切回直连后保留中转设置，方便下次切换；官方登录文件不会被修改。

历史文件缺失与旧路径
换电脑、换用户名或移动 .codex 后，数据库可能仍保存旧的历史文件路径。
软件优先使用有效的本目录路径；旧路径失效时，会查找本目录内同一会话
的唯一对应文件，先备份再修正路径。找不到文件时，跳过该会话并保留原记录，
继续有效历史和配置修复、连接切换。多个候选无法确定时仍停止，目录外文件不改。
两页预览显示可更新、跳过、待修正路径的数量和每条明细；补齐文件后可重扫。
路径修正可通过本次备份恢复。未知数据库结构、无法识别的历史格式、独立
profile 或外置 sqlite_home 等情况仍会停止；可取消历史兼容单独处理配置。

修复配置文件内容
1. 在“检查与修复”页选择 Codex 目录，再进入左侧第 3 项“配置内容修复”。
2. 读取当前配置或导入 TOML。默认显示脱敏内容并保持只读。
3. 需要手动编辑时，勾选“显示并编辑原文（可能含密钥）”。
4. 点击“检查并预览”，或“自动修复并预览”，查看错误、提示和脱敏差异。
5. 内容通过检查后，退出 Codex，再点击“备份并保存”。
6. 完成后重新打开 Codex。可导出脱敏检测报告，或在备份页恢复原文件。

自动修复仅处理完整 Markdown 代码围栏、字符串分隔符的弯双引号、
True/False 大小写，以及已明确识别的布尔字段中的字符串布尔值。
不会删除重复键，不猜提供方、模型或安全权限，不修改未知字段。
原配置即使损坏，也会先完整备份原始字节，再保存有效候选内容。
保留原 UTF-8 BOM 和换行方式；带 BOM 的 UTF-16 文件转换为 UTF-8。
本功能只修改 config.toml，不自动迁移历史记录。若更改提供方，
保存后可到“检查与修复”页同步历史记录标记。
原文与备份可能含密钥；报告和差异预览脱敏。检查范围有限，
不能验证接口网络、密钥权限及 Codex 全部版本与未来字段。

恢复
进入“备份与恢复”，选择相应备份。退出 Codex 后，点击“恢复所选备份”。
若相关文件已有新增内容，程序会停止自动恢复，避免覆盖新会话。
连续多次切换后，请从最新备份开始逐次恢复。

本工具仅在本机处理文件，不上传配置、不调用模型。
无需提前备份；修复、切换或保存前都会自动备份，失败时停止写入。
原始备份保存在所选 Codex 目录下的 repair-backups 中。
原始备份可能包含配置凭据，不要连同程序一起发给其他人。
